# Калькулятор выражений на TypeScript

**Работу выполнил:** Каргинов Тамерлан, группа 241-3210.

Это учебный проект: вводишь строку с числами и знаками плюс и звёздочка (умножение), программа считает результат. Умножение важнее сложения, как в обычной математике. Например для `12+3*4` сначала считается `3*4`, потом к двенадцати прибавляется двенадцать, итого 24.

По заданию я сделал отдельный класс стека, разбор строки в токены, перевод в обратную польскую запись (ОПЗ), подсчёт по ОПЗ, проверку допустимых символов и веб-страницу с формой.

---

## Структура проекта

- `src/stack.ts` — универсальный стек `Stack<T>` на массиве: положить, снять, посмотреть верхушку, проверка на пустоту.
- `src/calculator/validator.ts` — функция `assertExpressionCharacters`: если в строке есть что-то кроме цифр, пробелов, точки, `+` и `*`, выбрасывается ошибка.
- `src/calculator/expression.ts` — вся логика вычисления: токенизация, проверка токенов, ОПЗ, подсчёт. Снаружи экспортируется одна функция `evaluateExpression(строка): число`.
- `src/calculator/index.ts`, `index.html`, `style.css` — интерфейс в браузере.
- `src/demo-for-work.ts` — то же вычисление из консоли Node (readline).
- `src/tests/calculator.test.ts` — автоматические тесты. После `npm run build` они лежат в `dist/tests/calculator.test.js`, их запускает `npm test`.

Папка `dist/` создаётся компилятором TypeScript, туда копируется весь скомпилированный JavaScript из `src/`.

## Сборка и запуск

1. Установить зависимости: `npm install`
2. Собрать проект: `npm run build` (команда вызывает `tsc`)
3. Тесты: `npm test` (сначала снова сборка, потом `node --test` по файлу в `dist/tests/`)

5. Веб: удобнее открыть `src/calculator/index.html` через локальный сервер (например расширение Live Server), чтобы модули `import` работали как положено. После сборки скрипты подтягиваются из `dist/calculator/`.

## Как устроено вычисление (по шагам)

Всё начинается в `evaluateExpression` в файле `expression.ts`.

**Шаг 1. Обрезка пробелов по краям.** Пустая строка сразу ошибка.

**Шаг 2. Проверка символов** через `assertExpressionCharacters` из `validator.ts`. Разрешены только цифры, пробелы, точка для дробей, плюс и звёздочка.

**Шаг 3. Токенизация** функцией `tokenize`. Токен — это маленький кусочек смысла: либо одно число, либо один оператор. Я храню это в виде типа `Token`:

- если `kind` равен `"num"`, в поле `value` лежит число типа `number` (целое или с точкой);
- если `kind` равен `"op"`, в `value` лежит либо `"+"`, либо `"*"`.

Чтобы не гонять индекс строки по куче функций, завёл вспомогательный тип `Pos` — объект с одним полем `i`, это текущая позиция в строке. Числа читаю посимвольно, учитываю одну точку в дроби.

**Шаг 4. Проверка последовательности токенов** функцией `validateTokens`. Нужна схема «число, оператор, число, оператор, …» и в конце обязательно число. То есть токенов нечётное количество, на чётных местах (0, 2, 4…) стоят числа, на нечётных — операторы. Иначе выражение некорректно.

**Шаг 5. Перевод в ОПЗ** функцией `toRpn`. ОПЗ (обратная польская запись) — это когда сначала идут операнды, потом знак. Так проще считать стеком. Для приоритета операций у меня функция `opPrecedence`: у `*` приоритет 2, у `+` приоритет 1. Идём по токенам слева направо: числа сразу попадают в выходной массив `out`. Операторы кладу во второй стек `ops` типа `Stack<"+" | "*">`. Перед тем как положить новый оператор, снимаю со стека те, у кого приоритет не ниже текущего, и дописываю их в `out`. В конце снимаю всё, что осталось в стеке операторов. Так умножение «вылезает» раньше плюса там, где нужно.

**Шаг 6. Подсчёт по ОПЗ** функцией `evalRpn`. Завожу стек чисел `Stack<number>`. Снова иду по списку токенов в ОПЗ: число — просто кладу в стек; оператор — снимаю два верхних числа (сначала правый операнд `b`, потом левый `a`), считаю `a+b` или `a*b`, результат кладу обратно. В конце в стеке должно остаться ровно одно число — это ответ.

Итого цепочка такая: строка, проверка символов, список токенов, проверка чередования, ОПЗ, подсчёт по стеку.

## Типы и класс (что именно в коде)

Интерфейсов в проекте нет, зато есть типы и один класс:

| Имя | Где | Зачем |
|-----|-----|--------|
| `Pos` | `expression.ts` | Объект `{ i: number }` — позиция при разборе строки. |
| `Token` | `expression.ts` | Объединение двух вариантов: число или оператор (discriminated union по полю `kind`). |
| `Stack<T>` | `stack.ts` | Класс стека на массиве: `push`, `pop`, `peek`, `isEmpty`. |

Публичная точка входа для всей математики — **функция** `evaluateExpression(input: string): number`. Она либо возвращает число, либо бросает `Error` с текстом на русском (пустая строка, плохой символ, не то чередование токенов и т.д.).

## Что проверяют тесты

Файл `src/tests/calculator.test.ts` импортирует `evaluateExpression` из `../calculator/expression.js` (в собранном виде пути те же, только расширение `.js` для ESM).

1. **Приоритет умножения:** строка `12+3*4` должна дать 24.
2. **Несколько сложений подряд:** `1+2+3` даёт 6.
3. **Несколько умножений подряд:** `2*3*4` даёт 24.
4. **Смешанный порядок:** `1*2+3` даёт 5 (сначала умножение, потом сложение).
5. **Дроби и пробелы:** строка с пробелами ` 2.5 * 4 ` даёт 10.

Запуск: `npm test`.
